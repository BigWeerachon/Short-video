# PAAKIN Studio — เอกสารออกแบบ

วันที่: 2026-11-13 · สถานะ: รออนุมัติ

## 1. เป้าหมายและเหตุผล

สร้าง "สตูดิโอคอนเทนต์" ส่วนตัวสำหรับผลิตคลิปเล่าเรื่อง 2D แนวตั้งที่ soft-sell PAAKIN (www.paakin.com) และโพสต์ทั่วไปของเพจ Facebook
งานทุกขั้นทำผ่าน Claude Code บน cloud สั่งได้จากมือถือ มีทีมตัวละครแต่ละตำแหน่ง หัวหน้าคุมงานและรายงาน
ระบบต้องจำความผิดพลาดที่เคยเจอเพื่อไม่ให้เกิดซ้ำ และใช้ token ให้น้อยที่สุด

ที่มา: ตอนนี้งานทั้งหมดอยู่ในแชทเดียว ("นิทานขายเว็บ PAAKIN") ทุกคลิปต้องแปะคู่มือใหม่ แก้ปัญหาเดิมซ้ำ ไม่มีที่เก็บงานเป็นระบบ และเตรียมแคปชั่นกับโพสต์เองทีละแพลตฟอร์ม

## 2. Goals / Non-goals / Anti-goals

**Goals**
- สั่ง `/สร้างคลิป` พร้อมบท (.txt) และเสียง (.mp3) แล้วได้ MP4 9:16 1080×1920 30fps ตามคู่มือเดิมทุกข้อ
- สั่ง `/แคปชั่น` แล้วได้แคปชั่นแยก 4 แพลตฟอร์ม (YouTube Shorts, Facebook Reels, TikTok, IG Reels) แก้ไขได้และสร้างใหม่ได้
- สั่ง `/โพสต์` แล้วได้โพสต์ทั่วไปสำหรับเพจ Facebook เช่น โปรโมท ข่าวสาร หรือกิจกรรม
- มีคลังงานจัดหมวดละเอียด
- มีออฟฟิศพิกเซลที่เปิดในมือถือได้ ใช้ง่าย สะอาดตา เห็นสถานะงาน คลังงาน และรายงาน
- มีคลังความรู้และบันทึกบทเรียนที่ทุกตำแหน่งต้องอ่านก่อนทำงาน
- ใช้โมเดลตามความยากของงาน หัวหน้าทำ timeline ตั้งงบ token และรายงานผล

**Non-goals (เฟสนี้)**
- ยังไม่โพสต์อัตโนมัติ: ใช้แบบกึ่งอัตโนมัติ (ระบบเตรียมไฟล์และแคปชั่น คุณกดโพสต์เอง) ส่วนต่อ API จะทำในเฟสถัดไป
- ยังไม่สร้างเสียงพากย์เอง: คุณส่งไฟล์ ElevenLabs มาเหมือนเดิม
- ไม่สร้างภาพ AI แบบ 3D จริง
- ไม่สั่งงานหนักจากปุ่มในหน้าออฟฟิศ งานหนักสั่งผ่านแชท

**Anti-goals (ถ้าเป็นแบบนี้ถือว่าล้มเหลว แม้จะทำงานได้)**
- ทำผิดซ้ำในเรื่องที่บันทึกไว้แล้ว เช่น มีลายน้ำ มีเสียง noise ซับไม่ตรงเสียง หรือไม่มีฉากปิด
- ออฟฟิศรก ใช้บนมือถือยาก หรือกิน token ต่อคลิปเกินประมาณ 2%
- ใช้ Opus หรือ Fable กับงานที่ Haiku หรือ Sonnet ทำได้

## 3. ข้อจำกัด
- รันบน Claude Code cloud (container ชั่วคราว) งานที่ต้องเก็บต้อง commit และ push ขึ้น repo `BigWeerachon/Short-video`
- ใน container มี ffmpeg, Python+numpy, Node 22 และ Chromium/Playwright อยู่แล้ว ส่วน Whisper ใช้ไม่ได้ เพราะ alignment ใช้วิธีช่วงเงียบ+DP ตามคู่มือ
- ใช้แพ็กเกจ Claude Code ที่มีอยู่ ไม่ใช้ Claude API แยก
- Artifact ไฟล์ไบนารีได้ไม่เกิน 15MB ต่อไฟล์ ดังนั้น MP4 ส่งผ่านการแนบไฟล์ในแชท และเก็บใน repo ตามข้อ 6.5
- ภาพในคลิปต้องเป็น 2D flat vector ตามคู่มือ ส่วนพิกเซลใช้เฉพาะหน้าออฟฟิศ

- **Sonnet** ใช้กับงานเขียนและสคริปต์ทั่วไป
- **Haiku** ใช้กับงานตามแบบฟอร์มและงานจดบันทึก

## 6. ระบบหลัก

### 6.1 Pipeline คลิป (ตามคู่มือ 8 ขั้น พร้อม gate)
รับงาน → (1) ผู้อำนวยการวางแผนและทำ timeline → (2) วิศวกรเสียง align ได้ `words.json` แล้ว **gate: สรุปเวลาสำคัญให้คุณตรวจ** → (3) ผู้กำกับทำ shot list → (4) นักแอนิเมตสร้างฉาก → (5) นักวิจารณ์ตรวจ contact sheet (ไม่ผ่านให้ส่งกลับไม่เกิน 2 รอบ แล้วเรียกผู้อำนวยการ) → (6) ช่างตัดต่อ export MP4 → (7) นักการตลาดทำแคปชั่น → (8) บรรณารักษ์เก็บเข้าคลังและอัปเดตออฟฟิศ → ผู้อำนวยการส่งรายงาน

### 6.2 Engine กลางที่ใช้ซ้ำ (ส่วนที่ประหยัด token มากที่สุด)
ทำ `engine/` ครั้งเดียวจากคู่มือ ประกอบด้วย:
- rig IK 2-bone, ท่าเดิน, สีหน้า และฉากตัวละครแก๊งซ่า
- ซับไทยที่ตัดคำด้วย Segmenter และฟอนต์ Kanit
- กล้อง clamp, ฉากปิด และ player
- สคริปต์ align, ดนตรี/SFX และ export

แต่ละคลิปเขียนเพิ่มเฉพาะ shot list กับ prop ใหม่ จึงไม่ต้องเขียนตัวละครใหม่ทุกครั้ง

### 6.3 ความรู้และบทเรียน
- `CLAUDE.md` เก็บกฎถาวร 8 ข้อจากคู่มือ และลิงก์ไปไฟล์ความรู้
- `knowledge/manual.md` เก็บคู่มือฉบับเต็ม
- `knowledge/lessons.md` เป็นตารางปัญหา → วิธีแก้ → วันที่ → ตำแหน่งที่เกี่ยว ตั้งต้นด้วย 13 ข้อเดิม
- **ทุกครั้งที่คุณตำหนิหรือสั่งแก้** บรรณารักษ์ต้องบันทึกเพิ่มทันที ก่อนเริ่มงานทุกตำแหน่งต้องอ่านเฉพาะแถวที่ติดแท็กตำแหน่งตัวเอง วิธีนี้ประหยัด token กว่าให้อ่านทั้งไฟล์
- นักวิจารณ์ใช้ lessons เป็น checklist บังคับ

### 6.4 การบริหาร token
- ผู้อำนวยการตั้งงบต่อคลิปและบันทึกการใช้จริงในรายงาน
- ส่งต่องานระหว่างตำแหน่งด้วยไฟล์สรุปสั้น (`jobs/<id>/brief.md`, `handoff.md`) ไม่ส่งประวัติแชทต่อ
- ถ้าแก้แค่เสียงให้ remux ไม่ต้องเรนเดอร์ใหม่ และแก้เฉพาะช็อตที่ผิด

### 6.5 คลังงาน
- โครงสร้าง `library/<ปี-เดือน>/<id>-<ชื่อ>/` ภายในมี `meta.json`, บท, `captions.json` และ MP4
- MP4 เก็บผ่าน Git LFS ถ้าเปิดได้ ถ้าไม่ได้จะเก็บนอก repo และในคลังบันทึกไว้ว่าไฟล์อยู่ที่แชทไหน
- หมวด: ประเภท (คลิปนิทาน / โพสต์โปรโมท / ข่าวสาร / กิจกรรม), ซีรีส์, ตัวละคร, อารมณ์, ฟีเจอร์ PAAKIN ที่ขาย และสถานะ (ร่าง / รอตรวจ / พร้อมโพสต์ / โพสต์แล้วแพลตฟอร์มไหนบ้าง)

### 6.6 ออฟฟิศพิกเซล (Artifact บน claude.ai)
- ออกแบบสำหรับมือถือก่อน สะอาดตา มี 3 แท็บด้านล่าง:
  - **ออฟฟิศ:** แผนผังห้องแบบพิกเซล ตัวละครเดินไปหาตำแหน่งถัดไปเมื่อส่งต่องาน มีแถบงานปัจจุบันและ timeline
  - **คลังงาน:** การ์ดงานพร้อมตัวกรองหมวด กดแล้วเห็นแคปชั่นแยกแพลตฟอร์มพร้อมปุ่มคัดลอก
  - **รายงาน:** สรุปจากผู้อำนวยการ งบ token และบทเรียนล่าสุด
- สถานะเก็บในฐานข้อมูลของ Artifact (db capability) agents เขียนผ่าน ArtifactData เฉพาะตอนจบขั้น ประมาณ 8–10 ครั้งต่อคลิป
- แอนิเมชันทั้งหมดรันในเบราว์เซอร์ ไม่ใช้ token

### 6.7 คำสั่ง (skills ใน `.claude/skills/`)
`/สร้างคลิป`, `/แก้คลิป`, `/แคปชั่น` (สร้างใหม่หรือปรับเฉพาะแพลตฟอร์มได้), `/โพสต์`, `/วางแผนสัปดาห์`, `/รายงาน`, `/จำไว้` (บันทึกบทเรียนทันที)

## 7. ส่วนที่ปล่อยให้ผู้สร้างตัดสินใจ
- โครงไฟล์ภายใน engine และรายละเอียดภาพพิกเซล (คุมโทนสดใสให้เข้ากับแบรนด์)
- ถ้าใช้ Git LFS ไม่ได้ ให้ใช้ทางสำรองตามข้อ 6.5
- คลิปแรกจะทั้งสร้าง engine และทดสอบ pipeline ไปพร้อมกัน (โค้ดคลิปเก่าไม่ได้อยู่ใน repo จึงต้องเขียน engine ใหม่ตามคู่มือ)
